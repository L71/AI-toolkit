# ollama_service.py

A small Python utility for managing Ollama as a persistent macOS background
service — independently of Homebrew.

---

## Background: why does this exist?

When you install Ollama via Homebrew and start it with `brew services start ollama`,
Homebrew generates a launchd property list (plist) file and registers it with
macOS's service manager. This works, but has a frustrating limitation: there is
no official way to inject your own environment variables (such as `OLLAMA_HOST`)
into a Homebrew-managed service. The plist is owned and regenerated by Homebrew,
so any manual edits get silently overwritten on the next `brew upgrade` or
`brew services restart`.

### A brief primer on launchd and plists

macOS uses a subsystem called **launchd** to manage background services (similar
to `systemd` on Linux). Each service is described by a **plist** — an XML file
that tells launchd what binary to run, what environment variables to pass it,
whether to restart it on crash, and so on.

Plist files for user services live in `~/Library/LaunchAgents/`. Homebrew writes
its own plist there when you run `brew services start`. The problem is that
Homebrew considers that file *its own* — it can regenerate or delete it at any
time.

The clean solution is to create a **separate plist** with a different service
label that Homebrew is completely unaware of. That is exactly what
`ollama_service.py` does.

---

## What the script does

- Reads environment variables from a simple `KEY=VALUE` text file
  (`~/.ollama/env` by default).
- Generates a valid launchd plist at
  `~/Library/LaunchAgents/local.ollama.serve.plist`.
- Registers and manages that service via `launchctl` — the command-line
  interface to launchd.
- Leaves Homebrew's own plist completely untouched.

Because the service label is `local.ollama.serve` (not `homebrew.mxcl.ollama`),
Homebrew never interacts with it. The service survives `brew upgrade ollama`
without any intervention.

---

## Requirements

- macOS (any reasonably recent version)
- Python 3.9 or later (ships with macOS, or via Homebrew)
- Ollama installed via Homebrew (`brew install ollama`)

No third-party Python packages are required.

## Quick start

### 1. Stop the Homebrew-managed service (if running)

If you previously started Ollama via `brew services`, stop it first to avoid
two instances trying to bind the same port:

```bash
brew services stop ollama
```

### 2. Create your environment file

```bash
mkdir -p ~/.ollama
nano ~/.ollama/env
```

Add your desired settings, one per line:

```
# Make Ollama listen on all network interfaces
OLLAMA_HOST=0.0.0.0

# Allow requests from any origin (useful for local web UIs)
OLLAMA_ORIGINS=*

# Keep models in memory for 10 minutes after last use
OLLAMA_KEEP_ALIVE=10m
```

Lines starting with `#` and blank lines are ignored.

### 3. Install and start the service

```bash
python3 ollama_service.py install
```

This writes the plist, registers it with launchd, and starts Ollama immediately.
The service will also start automatically at every login.

### 4. Verify it is running

```bash
python3 ollama_service.py status
```

You should see something like:

```
Plist:   /Users/you/Library/LaunchAgents/local.ollama.serve.plist
Status:  running  (PID 12345)
Log:     /Users/you/.ollama/ollama.log
```

You can also confirm Ollama is reachable:

```bash
curl http://localhost:11434
# → Ollama is running
```

## Commands

| Command | What it does |
|---|---|
| `install [env_file]` | Write plist from env file, then load the service |
| `load` | Start the service (plist must already exist) |
| `unload` | Stop the service |
| `reload` | Stop then start (useful after editing the env file) |
| `status` | Show whether the service is running, plus its PID and log path |
| `uninstall` | Stop the service and delete the plist |

The optional `env_file` argument to `install` lets you point at any file:

```bash
python3 ollama_service.py install ~/my-configs/ollama-work.env
```

---

## Updating your configuration

Edit `~/.ollama/env`, then re-run `install` — it handles the stop/start cycle
automatically:

```bash
nano ~/.ollama/env
python3 ollama_service.py install
```

There is no need to manually unload first; the script detects a running service
and gracefully stops it before rewriting the plist.

---

## Logs

Both stdout and stderr from Ollama are written to:

```
~/.ollama/ollama.log
```

To follow the log in real time:

```bash
tail -f ~/.ollama/ollama.log
```

## Common environment variables

These are the most useful `OLLAMA_*` variables to put in your env file:

| Variable | Example | Effect |
|---|---|---|
| `OLLAMA_HOST` | `0.0.0.0` | Listen on all interfaces, not just localhost |
| `OLLAMA_ORIGINS` | `*` | Allow cross-origin requests (needed by some UIs) |
| `OLLAMA_KEEP_ALIVE` | `10m`, `1h`, `-1` | How long to keep a model loaded; `-1` = forever |
| `OLLAMA_MODELS` | `/Volumes/Data/ollama/models` | Store models on a different disk |
| `OLLAMA_CONTEXT_LENGTH` | `8192` | Default context window size |
| `OLLAMA_DEBUG` | `1` | Enable verbose debug logging |

---

## Coexisting with Homebrew

The script and Homebrew's service manager target entirely different plist files
and service labels, so they can coexist peacefully — as long as only one of them
is actively running Ollama at a time (otherwise both would try to bind port
11434 and one would fail).

A safe setup is: stop the Homebrew service once (`brew services stop ollama`),
then use this script exclusively going forward. If you ever want to revert,
run `python3 ollama_service.py uninstall` and then `brew services start ollama`.

## Files created by the script

| Path | Purpose |
|---|---|
| `~/Library/LaunchAgents/local.ollama.serve.plist` | The launchd service definition |
| `~/.ollama/env` | Your environment variable config (you create this) |
| `~/.ollama/ollama.log` | Combined stdout/stderr log from Ollama |

## Troubleshooting

**Service shows as stopped with a non-zero exit code**

Check the log for errors:
```bash
tail -50 ~/.ollama/ollama.log
```
A common cause is a typo in `OLLAMA_HOST` or a port already in use.

**`ollama binary not found` warning during install**

The script looks for Ollama at `/opt/homebrew/bin/ollama` (Apple Silicon) and
`/usr/local/bin/ollama` (Intel). If your Homebrew prefix is different, edit the
`OLLAMA_CANDIDATES` list near the top of the script.

**I want to check what is in the generated plist**

```bash
cat ~/Library/LaunchAgents/local.ollama.serve.plist
```

**Reverting completely**

```bash
python3 ollama_service.py uninstall
brew services start ollama   # hand control back to Homebrew
```
